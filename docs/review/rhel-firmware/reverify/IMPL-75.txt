D. THE SMOKE GATE: REPINNED, AND WHAT THAT GIVES UP
================================================================================

The decision is repin, not carry both. Plan section 7 priced the swap at 1.1 s
and the alternative at roughly +60 lines, estimated rather than measured because
it was not built. What settles it is not the timing:

  * The branch taken has a live, reproduced defect (CI 33373539104) and had
    never been applied against a real libvirtd anywhere -- not in CI, not on the
    rig, not in the Fedora acceptance run.
  * The branch given up has no known defect and the acceptance run applied it.
  * The branch taken is the delivery target's. variables.tf:60-66: "RHEL ships a
    raw .fd".
  * Carrying both means two VMs in one apply. DOMAIN, OVERLAY_VOL, SEED_VOL, MAC
    and MARKER_ID are script globals, and assert_volumes, assert_domain,
    assert_gone and cleanup all key off them -- four functions to parameterise,
    against a -5/+10 module fix. CLAUDE.md: unjustified surface area is a defect
    here, and a fix that adds more surface than the defect warrants is itself a
    problem.

WHAT NO GATE COVERS ANY MORE, stated once and plainly: libvirt selecting a
firmware from the host's own descriptors and materialising a varstore from no
template. That was scripts/smoke-libvirt.sh's only exercise of it, and this
lane removes it. What the module *emits* on that branch is still pinned offline
-- tests/libvirt-module.tftest.hcl asserts app01's os.firmware == "efi",
os.nv_ram == null, os.loader == null, os.loader_type == null and
os.loader_readonly == null -- so the loss is the libvirtd round trip, not the
expression. It is recorded in the script itself, at the tfvars, so a reader of
the gate finds it rather than a reader of this file.

A qcow2 pin is not an option on this runner class and that is measured, not
assumed: beside `firmware = "efi"` libvirt validates the pin against the host's
descriptors rather than deferring to it, all four Ubuntu descriptors declare
"raw", and a qcow2 pin is refused at define (CI 33374365926, 33374623746).

The four new assertions replace one (`contains "$xml" '<nvram'`). Three of them
are on libvirt's own output; the fourth is the refresh-drift check plan section
7 priced at 3.4 s. The regression gate for the module is the apply itself: put
either attribute back and `tofu apply` exits 1 before a single `check` runs.
