# vcows-deploy v0.1.0.0 — development tooling survey

Surveyed 2026-08-29 on `feature/scaffold` at `2fd966d`, by four agents plus this
orchestrator. Nothing in the repository was modified. Every tool named here was
installed and run against this repository or a real build of its image; where a
tool could not be installed, that is stated and the finding is marked as
hand-checked instead of measured.

Scope was "what tooling would help development, testing and building." The most
valuable thing it produced is not a tool. It is section 2.

## 1. Verdict

**Adopt CI first, and treat section 2 as a release blocker rather than a tooling
item.**

There is no automation of any kind in this repository today: no CI, no task
runner, no pre-commit hooks, no coverage configuration, no git hooks. Every gate
is run by hand and trusted. That is the largest gap, it is also the cheapest to
close, and the fix is smaller than expected because the libvirt-binding problem
turned out to have a one-line answer (4.1).

Against that, most of the tools a survey like this usually recommends do not
apply here, and several would actively make things worse. The IaC policy scanners
have no libvirt rules at all and would report a permanent clean bill of health
(5.1). `terraform-docs` would generate something thinner than the prose already
in `variables.tf` (5.4). A container structure-test tool cannot express what
`tests/test_image.py` already asserts (5.5). Those are recorded in section 5 so a
future session does not re-derive them.

Two claims the codebase might be tempted to make are false and are recorded here
with the measurement: the image build is **not** reproducible (5.7), and the
`README` command for setting up a development environment installs **nothing**
(3.1).

## 2. Act before the next delivery: CVEs in the pinned binaries

**`golang.org/x/crypto/ssh` is statically linked into both shipped Go binaries and
carries HIGH-severity CVEs.** Measured with trivy 0.74.0 against a real
`podman build` of this repository:

| Binary | CVEs | of which HIGH |
|---|---|---|
| `/usr/bin/tofu` (OpenTofu 1.12.6) | 21 | 10 |
| `terraform-provider-libvirt_v0.9.8` | 39 | 27 |
| Rocky 10.2 RPM set | 60 | 44 |

Among them **CVE-2026-39828**, unauthorized command execution via discarded SSH
permissions, and **CVE-2026-39831**, security-key bypass.

This is the transport the entire product runs on. `qemu+ssh://` is not incidental
here; it is the only channel to the hypervisor and the only network the air-gapped
site has.

Three things make this worth writing down rather than fixing casually:

1. **The pinning that makes the build trustworthy is what freezes the vulnerable
   code in place.** `TOFU_RPM_SHA256` and `PROVIDER_SHA256` in the `Containerfile`
   are correct and should stay. They also mean nothing drifts forward on its own.
2. **`container/manifest.py` cannot see this.** It runs `rpm -qa` and
   `tofu version -json`. A statically-linked Go binary's embedded module list is
   structurally invisible to an RPM query, and the provider is not an RPM at all.
   This is not a defect in `manifest.py`; it is outside what that mechanism can
   reach.
3. **grype does not find it.** Run against the identical image, grype produced 241
   matches, every one of them RPM-typed, and matched zero of the 283 Go modules
   syft catalogued in those two binaries. A future session should not conclude
   "we scanned it" from a grype run.

The remedy is a decision about upgrading the pinned OpenTofu and provider versions
and rotating the three hash fields, not a linter. Section 4.8's schema-diff
sequence is the safe way to carry that upgrade out.

## 3. Defects found while surveying

### 3.1 · The documented development setup installs nothing

`README.md:226` says:

```
uv pip install -e '.[dev]'
```

`pyproject.toml` declares `[dependency-groups] dev = [...]`, not
`[project.optional-dependencies]`. There is no `dev` extra. `uv` emits
`warning: ... does not have an extra named "dev"` and installs zero development
tools, exit 0. Anyone following the README gets a venv with no pytest, no ruff and
no ty, and only a warning to tell them.

Working form, verified: `uv pip install -e . --group dev`

Any Makefile or CI added later must not copy the README's command.

### 3.2 · `xorriso` is an undocumented test prerequisite

`tests/test_seed_iso.py:61` shells out to `xorriso` and is not gated. It passes on
the maintainer's box because `xorriso-1.5.6-6.el10` happens to be installed. In a
clean environment the test fails with `FileNotFoundError: xorriso`. It appears in
no requirements list, no README prerequisite section and no `conftest.py` gate.

This is deliberate in spirit — `test_seed_iso.py`'s own header explains that
pycdlib writes and xorriso reads back, because a builder verified only by itself is
not verified. The dependency just needs recording.

### 3.3 · Two of five version consumers are unchecked

`orchestrator/__init__.py:4-12` claims five consumers cannot drift.
`tests/test_version.py` asserts three: `test_format_is_four_digit`,
`test_marker_carries_the_version`, `test_pyproject_agrees`. The image tag
(`Containerfile:42`, `ARG VCOWS_VERSION=0.1.0.0`) and the OCI label are not
asserted, and `README.md` hardcodes `0.1.0.0` in its `podman run` examples.

Already recorded as an open item at
`docs/2026-08-29-remediation-checklist.md:175`. Noted here because it is the
reason no release-versioning tool is recommended (5.6): the gap is one assertion,
not a missing tool.

## 4. Adopt

Ordered by leverage. Each item states the evidence measured in this repository.

### 4.1 · T1 — GitHub Actions CI

**The libvirt-binding problem does not require a Rocky container job.** Ubuntu
24.04 ships `python3-libvirt 10.0.0-1build1` in main, installed to
`/usr/lib/python3/dist-packages`, and `uv venv --python /usr/bin/python3
--system-site-packages` picks it up because Debian's patched `site.py` exposes
dist-packages the same way. Verified by running the full loop inside a
`podman run ubuntu:24.04` container matching `ubuntu-latest`:

```
315 passed, 40 skipped
ruff check / ruff format --check clean
ty check clean
```

This matters more than it looks. `tests/fake_libvirt.py:25` and
`tests/test_libvirt_preflight.py:15` do a real `import libvirt` at module scope, to
construct genuine `libvirt.libvirtError` instances. The binding is not confined to
the gated rig tests; most of the default suite needs it.

```yaml
name: ci
on: { pull_request: {}, push: { branches: [master] } }
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: sudo apt-get update -qq && sudo apt-get install -y -qq python3-libvirt xorriso
      - uses: astral-sh/setup-uv@v3
        with: { enable-cache: true }
      - run: uv venv --python /usr/bin/python3 --system-site-packages
      - run: uv pip install -e . --group dev
      - run: .venv/bin/ruff check --output-format=github .
      - run: .venv/bin/ruff format --check .
      - run: .venv/bin/ty check --output-format=github
      - run: .venv/bin/python -m pytest -q -rs
```

Both ruff and ty support `--output-format=github` natively, which gives inline PR
annotations with no additional tooling. Estimated under a minute: ~15s apt, ~10s
cached deps, ~15s checks.

`xorriso` in the apt line is 3.2, not incidental.

### 4.2 · T2 — Makefile

`make-4.4.1-9.el10` is preinstalled on Rocky 10. `just` is in no Rocky 10
repository (`dnf list just --available` returns no matching packages), so it would
need a third-party source on the one platform that matters. `nox` fights
`--system-site-packages` by default, and adds a PyPI dependency for no gain. `uv`
has no first-class multi-target task runner.

```makefile
venv:
	uv venv --python /usr/bin/python3 --system-site-packages
	uv pip install -e . --group dev

fmt:      ; .venv/bin/ruff format .
lint:     ; .venv/bin/ruff check .
type:     ; .venv/bin/ty check
test:     ; .venv/bin/python -m pytest -q -rs
test-all: ; VCOWS_GATES=tofu .venv/bin/python -m pytest -q -rs
check: lint fmt type test
```

Have CI call the same targets, so the developer loop and the gate cannot drift.

### 4.3 · T3 — trivy, on the build host

Found what section 2 reports. Also carries a dedicated Rocky advisory source —
confirmed live in its output: `[rocky] Detecting vulnerabilities... os_version="10"`.

```
trivy image --input <(podman save --format docker-archive localhost/vcows-deploy:0.1.0.0)
```

The vulnerability database pulled 110 MB from `mirror.gcr.io/aquasec/trivy-db:2`
in about ten seconds, no authentication, no configuration. Build-host only.
Nothing about this works at the air-gapped site, nor should it.

**grype is rejected specifically, not as a coin-flip between similar tools.** See
5.2.

### 4.4 · T4 — syft, on the build host

Complements `container/manifest.py`; it does not replace it. Measured on the built
image: 456 components — 161 RPM (matching `manifest.py`'s own count almost
exactly), 12 Python, and **283 Go modules** read from the embedded build
information in `/usr/bin/tofu` and the provider binary.

`manifest.py` stays authoritative for the build-time archival record: git SHA,
base digest, provider lock hash, source-RPM list for the GPL sidecar. Syft is the
only thing here that reaches inside the two Go binaries, and its SPDX/CycloneDX
output is the format a downstream auditor expects, which `manifest.json`'s bespoke
schema is not.

This distinction matters because the project deliberately prefers one
mechanism to two, and rejected a second air-gap mechanism on exactly that
principle. This is not that. The two tools see disjoint sets of dependencies.

### 4.5 · T5 — pytest-cov

`coverage` 7.16.0 is already present as a mutmut transitive dependency, but
`pytest_cov` is not installed. **No conflict with mutmut:** its `code_coverage.py`
constructs `coverage.Coverage(data_file=None)` in-process and reads line hits off
the object, never writing a `.coverage` file, so the two cannot clobber each other.

```toml
[tool.coverage.run]
branch = true
source = ["orchestrator"]

[tool.coverage.report]
fail_under = 80   # set from a first real report, not guessed
exclude_also = ["if TYPE_CHECKING:"]
```

### 4.6 · T6 — pre-commit with gitleaks

Confirmed compatible with the `--system-site-packages` venv. Every hook here is
static analysis; none imports `orchestrator` or `libvirt`, so pre-commit's
isolated per-hook environments never meet the binding problem. `tofu fmt` runs as
`language: system` against the already-required binary.

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.16.5
    hooks: [{id: ruff, args: [--fix]}, {id: ruff-format}]
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks: [trailing-whitespace, end-of-file-fixer, check-yaml]
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.21.2
    hooks: [gitleaks]
  - repo: local
    hooks:
      - id: tofu-fmt
        entry: tofu fmt -check -recursive orchestrator/backends/libvirt/tofu
        language: system
        pass_filenames: false
```

Gitleaks rather than GitHub's native secret scanning as the primary control: the
native one is push-protection shaped and tuned for vendor token formats. This
repository's risk surface is `ssh_keyfile` and `known_hosts` paths and a run
directory documented as holding cleartext credentials indefinitely, which wants a
custom rule.

### 4.7 · T7 — ruff `S`, plus nine targeted suppressions

Ten candidate rule families were run with `--statistics` against `orchestrator/`.
Real hit counts, not estimates:

| Family | Hits | Verdict |
|---|---|---|
| `S` | 12 | Adopt with suppressions |
| `TRY` | 14 (13× TRY003) | Skip, stylistic |
| `TID252` | 27 | Skip, fights the relative-import convention |
| `PL` | 19 (17× PLC0415) | Skip, see below |
| `PTH` | 3 | Skip, no bugs behind them |
| `ARG` | 2 | Skip, both interface-contract parameters |
| `C4`, `RET`, `LOG`, `G` | 0 | Nothing to select |

The `S` hits are all already-reviewed: six `S314` parsing `dom.XMLDesc` /
`pool.XMLDesc` output (libvirt's own output from a hypervisor this tool manages,
not attacker-supplied, and `defusedxml` is not RPM-available anyway), three `S603`
argv-list `subprocess.run` calls in `tofu.py` with no `shell=True`, and three
`S101` internal-invariant asserts documented inline. Add `"S"` to `select` and
suppress those nine with `# noqa` carrying the existing one-line justification.
The value is detecting the *next* subprocess or XML call, not re-litigating these.

`PLC0415` deserves its own note for a future session: those 17 hits are the
deliberate `import libvirt` calls inside `destroy.py` functions, deferred so the
modules load in the fake-libvirt test environment without the RPM present.
Enforcing that rule would fight a pattern the test suite depends on.

### 4.8 · T8 through T11, and the smaller items

- **T8 · hypothesis**, three surfaces only. `qcow2.virtual_size` (unpacks a 32-byte
  header; property-test arbitrary `u64` sizes and garbage past the header),
  `Marker.to_json`/`from_json` (round-trip over arbitrary names, generalizing the
  existing hand-picked `test_xml_payload_needs_no_escaping`), and
  `schema._parse_interface`/`_check_nics` (real CIDR math over arbitrary prefix
  lengths and dual-stack mixes). Not `cli.py` or `tofu.py` — subprocess
  orchestration, not parsing. Not `config.py` — jsonschema validation is
  declarative.
- **T9 · `types-pyyaml`.** `yaml.safe_load()` at `config.py:120` resolves to
  `Unknown`, confirmed with `reveal_type`. `pycdlib` ships `py.typed` and
  `jsonschema` is PEP 561-typed, so this is the only stub gap worth filling. The
  permanent ceiling is `libvirt.py`: the RPM binding is one untyped file with no
  stub package on PyPI, so every call into it stays `Unknown` under any checker.
- **T10 · hadolint**, with `--ignore DL4006 --ignore DL3003`. Only two hits and both
  are false positives here: the `DL4006` pipe is `echo "$SHA file" | sha256sum -c -`
  where `echo` cannot fail, and the `DL3003` `cd /tmp/warm` is inside one transient
  `RUN` that creates and removes the directory in the same layer, while the real
  `WORKDIR /` at `Containerfile:167` is set deliberately for the `-v ./runs:/runs`
  mount.
- **T11 · cosign `sign-blob`.** Tested end to end against a `podman save | gzip`
  tarball under `unshare -rn`. By default signing tries to write to the public
  Rekor log and verification fetches TUF metadata from `tuf-repo-cdn.sigstore.dev`;
  both fail with no network. With `--tlog-upload=false` at sign time and
  `--insecure-ignore-tlog` at verify time, both succeeded with nothing but a local
  public key file. Private key stays on the build host, public key ships beside the
  tarball, verified at the site with zero network.
- **`tofu fmt -check -recursive`** as a gate. Ran it: exit 0, no diff. Already clean,
  so this only guards against regression.
- **pytest-randomly.** No order dependency exists today (every environment mutation
  in the suite goes through `monkeypatch`, which auto-reverts), so this is
  insurance rather than a fix.
- **A skip-reason meta-test.** `pytest -q -rs` gives `330 passed, 25 skipped`, all 25
  from `test_image.py` (needs `VCOWS_IMAGE`) and `test_libvirt_rig.py` (needs
  `VCOWS_RIG_URI`). `conftest.py` already carries the enforcement mechanism —
  `VCOWS_GATES=<name|all>` turns a named gate's skip into a hard failure. What is
  still missing is anything asserting that a bare run produces *only* those two
  skip reasons; a new accidental skip elsewhere would pass silently forever. Add
  that assertion plus `--strict-markers`. This is the remaining half of
  F-TEETH-05.
- **Dependabot** for `uv.lock` and `github-actions`. It has native `uv` support and
  drives the real `uv` CLI, so `[dependency-groups]` needs no separate parsing path.
  Known rough edges in dependabot-core (case sensitivity, transitive lag) argue for
  a periodic manual `uv lock --upgrade` regardless.
- **Provider schema-diff on upgrade**, as a documented runbook rather than a tool.
  `docs/provider-schema-0.9.8.json` is already committed and cited as ground truth
  in `render.py` for the `loader_readonly` string-versus-boolean disagreement, but
  nothing diffs it on an upgrade. The sequence: `tofu providers mirror` the
  candidate on a connected host, `tofu providers schema -json` into
  `docs/provider-schema-<new>.json`, diff against the committed file, bump
  `version = "= X"`, regenerate the lock with
  `tofu providers lock -fs-mirror=.tools/tofu-mirror` (a lock built against the
  registry has different hashes), then rerun `tofu validate` and `tofu test`. The
  detection step is already automated by the existing gates; only the writing-down
  is missing. This is also the mechanism section 2's upgrade should travel through.

### 4.9 · CI jobs beyond the fast loop

- **tofu module gate**, separate job. Needs a provider mirror on disk, which needs
  `tofu providers mirror` against the real registry — fine in CI, and must be
  labelled CI-only so nobody mistakes it for a production shortcut. Cache it keyed
  on `PROVIDER_VERSION`; it is a ~26 MB download. Run with `VCOWS_GATES=tofu`.
- **Image build**, gated to `master` and tags, not every PR. The build does a real
  `dnf install`, downloads the tofu RPM and warms the plugin cache
  (`Containerfile:56-138`), so it is meaningfully heavier than the fast loop —
  estimated 2 to 5 minutes uncached. It also needs `.tools/tofu-mirror` rebuilt
  first, since that directory is `.gitignore`d; any automation must rebuild it from
  the committed lock rather than assume it exists.
- **mutmut**, on a weekly `schedule:` or `workflow_dispatch`, never as a PR gate.
  Mutation runs re-execute the suite per mutant; blocking every PR on that is
  expensive for uncertain payoff at this size.
- **The rig gate cannot run in hosted CI** and should be left an honest named skip.
  See 5.8.

## 5. Rejected, with the reason

Recorded so a future session does not re-derive them.

### 5.1 · checkov, trivy config, tfsec, conftest/OPA

All ship rule sets built for `aws_*`, `azurerm_*`, `google_*` and `kubernetes_*`
resource types. **None has any rule referencing `libvirt_domain`, `libvirt_volume`
or `libvirt_cloudinit_disk`.** Running any of them here produces a permanent
"0 findings" report, which is worse than no gate because it reads as a passed
security review and is not one.

This is a reject, not a defer. There is no future version of the recommendation
that becomes true without libvirt-specific rules that do not exist and are not
being written.

`conftest`/OPA fails for a second reason: `tests/libvirt-module.tftest.hcl` already
asserts the things Rego would assert (`features.acpi == true`,
`os.loader_readonly == "yes"`) natively, against a mocked apply, with no second
toolchain and no policy language to context-switch into.

### 5.2 · grype

Rejected on a measured head-to-head against trivy on the identical image: 241
matches, 100% RPM-typed, and **zero** matches against the 283 Go modules syft
catalogued in the same two binaries. It missed every CVE in section 2. This is not
a preference between comparable tools.

### 5.3 · tflint

No official libvirt ruleset exists. Hand-checked the module against the bundled
`terraform` ruleset: `terraform_unused_declarations`, `terraform_naming_convention`,
`terraform_typed_variables`, `terraform_documented_variables`,
`terraform_required_version`, `terraform_required_providers` and
`terraform_standard_module_structure` are all already clean. The one rule with
anything to say is `terraform_comment_style`, which would flag essentially every
comment in the module because the codebase deliberately uses `//` rather than `#`.

Nothing tflint sees would have caught any of the acceptance run's five real
defects (`docs/archive/acceptance.md`) — transport mismatch, credential parameter
spelling, format mismatch, missing ACPI, cloud-init netplan idiom. Those are
runtime and semantic, which is exactly the class the mock-provider `tftest.hcl`
approach was built for.

### 5.4 · terraform-docs

Renders only the `description` string per variable into a table. HCL has no
attribute-level description syntax, so it cannot see the nested-object comments
that carry the actual reasoning in `variables.tf` — for instance the note that
capacity belongs on the overlay because vol-upload writes the golden image's header
from offset 0 and silently discards whatever the base volume declared. A generated
README would be strictly thinner than the source, plus one more artifact to keep in
sync.

### 5.5 · container-structure-test and similar

`tests/test_image.py` already runs the built image with `--network=none`, asserts
the OCI labels are not inherited from the Rocky base, asserts `manifest.json`
content, asserts the RPM-versus-interpreter binding, and runs a real
`tofu init/validate/plan` against the baked mirror asserting it fails at exactly
the hypervisor dial. A structure-test tool checks file existence and command
output; it cannot express "plan must fail here and only here."

### 5.6 · bandit, mypy/pyright, just, nox, release-versioning tools

- **bandit** — ruff's `S` family already surfaced the only 12 candidate lines, all
  triaged. A second scanner re-reports the same lines with its own config file.
- **mypy / pyright** — `ty check` passes clean today and is not doing so vacuously:
  106 of 118 top-level functions carry return annotations. Both alternatives face
  the identical untyped-`libvirt.py` ceiling, so switching trades one pre-1.0 pin
  for a different maintenance burden with nothing gained.
- **just, nox** — see 4.2.
- **bump2version / commitizen / semantic-release** — one four-digit version with one
  source file. The gap is the missing assertion in 3.3, not a missing tool.
- **Full Renovate automation of the Containerfile hash ARGs** — verified it cannot
  recompute an arbitrary artifact's SHA256 or a `.terraform.lock.hcl` `h1:` hash.
  It handles the `BASE_IMAGE`/`BASE_DIGEST` pair well via a `customManagers` regex
  with `datasourceTemplate: docker`; `TOFU_RPM_SHA256`, `PROVIDER_SHA256` and
  `PROVIDER_LOCK_HASH` would still need a human. Adopting it as "automatic" would
  create false confidence.
- **syrupy / pytest-regressions** — the hand-rolled golden files
  (`tests/golden/libvirt.tfvars.json`, byte-for-byte in `test_libvirt_render.py`
  and `test_tofu_module.py`) are deliberate and documented. Migrating is lateral.
- **pytest-xdist** — `--durations=10` shows the 24s suite is dominated by two tests
  shelling out to the real `tofu` binary (5.81s + 5.58s). The rest is fast. Revisit
  if CI or suite size changes.
- **pytest-timeout** — no hang exists today, but `tofu.py` documents that `plan` and
  `apply` deliberately carry no timeout while `init`/`output`/`version` get
  `SHORT_TIMEOUT=120`. A wedged apply in a test double would hang indefinitely.
  Cheap net, not urgent until CI exists.
- **defusedxml** — would have to be a runtime dependency the air-gapped image cannot
  source as an RPM, for XML that is not attacker-controlled.

### 5.7 · The claim that this build is reproducible

**Measured false.** Two back-to-back builds with identical `GIT_SHA` and differing
`BUILD_DATE`, as the documented build command produces: **all 13 layers differ**,
including the `dnf install` and tofu-RPM-install layers which never reference
`BUILD_DATE`. `podman inspect --format '{{.Created}}'` differs as expected with no
`SOURCE_DATE_EPOCH`.

Recorded with the same discipline as the pycdlib finding, where a seed-ISO
reproducibility claim turned out false because pycdlib embeds 27 `time.time()`
calls. Do not assert reproducibility here without a diff.

If it becomes a requirement the levers are `podman build --timestamp=<epoch>` plus
keeping `BUILD_DATE` out of anything affecting layer content — it currently only
affects the label and manifest layer, which is fine to leave variable — but RPM
install order and dnf transaction metadata would still need investigating. Given
the project already treats archivability via `manifest.json` rather than
bit-for-bit reproducibility as the goal, this is a later item.

### 5.8 · `VCOWS_GATES=all` in hosted CI

`tests/test_libvirt_rig.py` needs a reachable hypervisor via `VCOWS_RIG_URI`. No
GitHub-hosted runner has one. Setting `VCOWS_GATES=all` would either hard-fail
every run or get "fixed" by re-adding a skip, which reproduces precisely the
vacuous-pass pattern recorded at `docs/2026-08-29-review.md:365`.

Set `VCOWS_GATES=tofu` (and `image` in the build job) and leave the rig a named,
documented skip, with the job summary saying which gates ran and which are
structurally out of reach. That distinction is the difference between an honest
skip and the one the review criticised.

## 6. Not investigated

- Runtime observability, logging and metrics tooling. Out of scope for a
  development-tooling survey and arguably wrong for a tool that runs once and exits.
- Anything requiring network at the deployment site. Disqualified by the air gap
  before evaluation.
- The `podman build` of the image was performed twice for the reproducibility
  measurement in 5.7; both images and their dangling layers were removed afterward.
- Test coverage gaps in the OpenTofu module itself, beyond noting two: the
  `base_volume.create == false` path falling back to `var.base_volume.path`, and
  the `devices.interfaces[*].source.bridge` branch. Both are type-checked via the
  `console` gate but never behaviour-asserted with a mock apply. Closing them is a
  second `run` block mirroring the existing pattern, which is test work rather than
  tooling.
